# OnlineLearning MPC

## Overview

OnlineLearning is research software for model-predictive control (MPC) of a thermal or district-heating system. The public entry point runs an offline simulation against a bundled functional mock-up unit (FMU).

## Scientific purpose

The software compares learned prediction strategies inside a receding-horizon controller. It is intended for implementation study and offline experimentation. The repository does not provide an enabled live-plant workflow or enough verified metadata to claim exact reproduction of article results.

## Methodology

At each controlled step, the runtime reads the simulated state, optionally updates model state, solves a constrained MPC problem with CasADi and IPOPT, records diagnostics, applies the first control move, and advances the FMU. Timing, constraints, channel order, scaling, and trained-model contents are scientific inputs; consult the [architecture](docs/public/architecture.md) and source configuration before interpreting results.

## Repository architecture

- [Main_OnlineLearningMPC.py](Main_OnlineLearningMPC.py): command-line entry point.
- [src/config/parameters.py](src/config/parameters.py): parameter construction, input loading, and preflight checks.
- [src/runtime/controller_runner.py](src/runtime/controller_runner.py): control loop, FMU interaction, persistence, and error logging.
- [src/class_MPC.py](src/class_MPC.py): MPC problem construction and solution.
- [src/model_strategies.py](src/model_strategies.py): strategy-specific behavior.
- [NNmodels](NNmodels): the bundled `NARX_net.mat` model.
- [FMUs](FMUs): the bundled `DHN_sim.fmu` simulation model.
- `src/utils/data/`: bundled electricity-price and heat-load CSV inputs.
- `Solutions_experimental/`: retained experimental result artifacts; these are not generated by a new run and are not established as article-reproduction baselines.

See the [detailed architecture](docs/public/architecture.md).

## Supported model strategies

`--Model` accepts `NNARX`, `GP`, or `BLL`; the default is `NNARX`.

- **NNARX** uses neural-network autoregressive predictions.
- **GP** applies an online Gaussian-process residual correction to NNARX.
- **BNNExp** is exposed by the CLI as `BLL`; it updates a Bayesian last layer and adds uncertainty-aware exploration behavior.

## Requirements

Use Conda on Windows with Python 3.10. [environment.yml](environment.yml) declares the numerical, optimization, FMU, and model dependencies. FMU execution depends on native pyFMI/Assimulo support and is not claimed to be platform independent. The checked-in `env/` directory is a local artifact, not an installation mechanism.

## Installation

Run from the repository root in Windows PowerShell:

```powershell
conda env create --prefix .\env --file environment.yml
conda activate .\env
```

To update an existing environment:

```powershell
conda env update --prefix .\env --file environment.yml --prune
```

The preserved environment audit export is [docs/public/environment-lock.txt](docs/public/environment-lock.txt).

## Quick start

**Smoke test:**

```powershell
python smoke_test.py
```

This validates imports, the representative GP configuration, required assets, and IPOPT availability. It does not run an FMU trajectory.

## Debug simulation

**Debug simulation:**

```powershell
python Main_OnlineLearningMPC.py --Debug --Model NNARX
```

Debug and `NNARX` are the defaults, so omitting `--Debug` and `--Model NNARX` is equivalent. Replace `NNARX` with `GP` or `BLL` to select another strategy. The runner loads `FMUs/DHN_sim.fmu`, uses the bundled model and CSV inputs, and writes local results.

## Live plant execution

Live plant execution is not supported by the public entry point. `--Live` is retained only as a safety boundary and raises `RuntimeError` before configuration or connector construction. This repository provides no public procedure for connecting to a plant.

## Input data and trained models

The current runtime assets are:

- `src/utils/data/DayAhead_ZonalPrices.csv`;
- `src/utils/data/DHN_ground_truth.csv`;
- `NNmodels/NARX_net.mat`;
- `FMUs/DHN_sim.fmu`.

Record the selected strategy, configuration, environment, input ordering, units, and exact asset bytes for any scientific run. Provenance and redistribution rights for these assets have not been established in the public documentation.

## Outputs and result files

New runs create `Solutions/<Model>/<ddmm>/` and append CSV files for measured and predicted outputs, recurrent predictions, control actions, boiler predictions, slacks, exploration, cost, computation time, solver status, and configuration. A pickle stores Bayesian `theta` and `sigma` arrays. Exceptions are appended to `LogsFolder/Exceptions.log`.

`Solutions_experimental/` contains existing experimental artifacts. Their relationship to a publication and their redistribution status require scientific-owner review.

## Reproducing the published results

Current support is limited to:

1. **Inspection:** review source, configuration, and bundled assets.
2. **Smoke test:** validate imports and preflight checks with `python smoke_test.py`.
3. **Debug simulation:** execute the FMU controller path on the supported Windows/Conda stack.

Exact article reproduction is not established. The current tree does not include the previously referenced numerical baseline JSON files, asset manifest, article configuration, or owner-approved tolerances.

## Tests and validation

**Test:**

```powershell
python -m unittest discover -s tests -p "test_*.py"
```

**Publication validation:**

```powershell
python tests/validate_publication.py
```

The latter compiles Python sources, runs the smoke test, and runs the unit tests. The files `tests/validate_fmu_baseline.py` and `tests/validate_strategy_baseline.py` remain in the tree, but they are not runnable with the current public documentation assets because their required baseline and manifest JSON files are absent.
